# Publication operations

## Version and toolchain

The site uses one current version until the first compatible public release.
Node 24, npm's committed lockfile, and Docusaurus 3.10.2 are exact repository
inputs. Repeatable jobs use `npm ci`; dependency upgrades are reviewed changes.

## Search privacy and cost

Search is deliberately disabled while the public site awaits crawler review.
The site is deployed on GitHub Pages; the project may now apply for Algolia DocSearch.
Its hosted
crawler sends public page content to Algolia and visitor queries to that
service, so the privacy boundary and free public-program eligibility must be
reviewed before repository configuration is enabled. Navigation does not
depend on the crawler, and pre-crawl state is never described as working search.

## Accessibility

The authoring baseline uses semantic headings, keyboard-operable Docusaurus
navigation, visible focus behavior, responsive layouts, contrast-aware themes,
and reduced layout complexity. #34 owns full browser accessibility smoke proof
before publication; the production build alone is not that proof.

## Permissions and rollback

The Pages workflow has least-privilege read access while building. Only its
deployment job receives `pages: write` and `id-token: write`, and it targets the
protected `github-pages` environment. The Pages source is GitHub Actions and the
M0 project-site deployment has been verified publicly. #34 still owns the final
default-branch publication, accessibility, search, navigation, and rollback
evidence. Main CI cannot deploy.

GitHub retains deployments and their immutable source revisions. A rollback is
a reviewed revert or an explicit redeployment of a previously verified
revision through the same workflow—never a workstation upload or direct
mutation of a `gh-pages` branch. An administrator must select GitHub Actions as
the Pages source; that one-time setting is visible external state, not startup
automation.
