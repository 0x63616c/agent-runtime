## Release scope

### H1 — Subscription-backed model support is only fixtures/preflight  `🔴 high · L · CONFIRMED`

**Current:** `internal/providers/codexsubscription/lifecycle.go:39-47` explicitly defines a process-local offline fixture and says durable deployment coordination is future work. `cmd/subscription-model-canary/main.go:1-36` supports only preflight; its workflow makes no provider call. `evidence/requirements-ledger.json:842-859` leaves MOD-001 through MOD-005 not started.

**Proposed:** Implement the model-role composition around an officially supported Codex process, use a durable lifecycle/fence store, and replace preflight-only canary with a protected real invocation/recovery canary retaining redacted evidence.

**Why:** MOD-001–005 and EX-001 cannot be delivered while the only route is a safe stub.

**Verification:** Exercise the public Durable Chat path through a credentialed protected canary; prove reconnect/recovery and enforce no credential in outputs, logs, artifacts, or state.

## Security

### H2 — Normalized model adapter allows plaintext bearer transport  `🔴 high · M · CONFIRMED`

**Current:** `internal/runtimemodel/http_adapter.go:50-53` accepts an `http` origin, `:58-62` uses `http.DefaultClient` by default, and `:93-99` adds a bearer credential before that request. No timeout, transport, or redirect policy is configured.

**Proposed:** Require HTTPS by default; permit HTTP only via an explicit loopback-only unsafe development option. Own a bounded HTTP client with a timeout and redirect refusal.

**Why:** A bad endpoint configuration can send provider credentials and invocation metadata in plaintext or on redirect.

**Verification:** Add rejection tests for HTTP/non-loopback and redirects, and a successful TLS-server test.

### H3 — Durable object storage always disables TLS  `🔴 high · M · CONFIRMED`

**Current:** `internal/runtimeapiprocess/config.go:47-52,105-116` has no transport-security field for content storage. `internal/runtimeapiprocess/run.go:271` hard-codes MinIO `Secure: false`. `internal/temporalpayloadruntime/factory.go:108-138` already has configurable secure transport.

**Proposed:** Add explicit content transport/TLS configuration; require TLS outside a narrowly declared local-only path, with CA/identity configuration where needed.

**Why:** Content and S3 credentials travel unencrypted if MinIO moves outside a fully trusted in-cluster network.

**Verification:** Configuration tests reject plaintext in production composition; integration test succeeds against TLS MinIO and validates the local-only exception.

## CI

### M1 — Main CI runs the Go linter twice  `🟠 medium · S · CONFIRMED`

**Current:** `.github/workflows/ci.yml:36-43` runs GolangCI then `just check`; `Justfile:4-14` runs GolangCI inside `just check`.

**Proposed:** Keep one authoritative lint invocation—prefer `just check` so local and hosted gates remain identical.

**Why:** It wastes CI time and risks differing action-versus-local lint behavior.

**Verification:** Run `just check` locally and the hosted `main-ci` check job once; confirm lint remains covered exactly once.

## Operability

### M2 — CONNECT tunnels have no graceful termination policy  `🟠 medium · M · CONFIRMED`

**Current:** `internal/egressproxy/proxy.go:195-224` hijacks CONNECT connections and copies until either side ends without registering them. `cmd/egress-proxy/main.go:53-74` only invokes `server.Shutdown(context.WithoutCancel(ctx))`; Go does not close or await hijacked connections. The CONNECT tests cover data forwarding but no shutdown/tunnel-termination case.

**Proposed:** Track active CONNECT tunnels; on termination stop accepting new work, allow a bounded grace period, then force-close remaining client and upstream pairs. Add a held-tunnel process test.

**Why:** Shutdown is abrupt and unobservable for active model-provider streams.

**Verification:** Hold an allowed CONNECT tunnel, send SIGTERM, and assert bounded completion plus explicit closure accounting.
