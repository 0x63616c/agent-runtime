# Proposed `AGENTS.md` for Agent Runtime

This is the proposed always-loaded operating contract. It intentionally adopts the active Software Factory style guide's rules, while replacing Factory-only Ticket/GitHub/Kubernetes details with the Agent Runtime domain. Before the first source package is created, make this document the repository's root `AGENTS.md` and add the exact paths/commands as they become real. Do not leave future commands as if they worked today.

```markdown
# AGENTS.md — Agent Runtime

This file governs every active directory in this public monorepo. Read it before changing code, tests, examples, generated output, deployment, skills, or documentation.

## What this is

Agent Runtime is a durable, usable platform for session-based agents. It owns sessions, turns, streamed events, cancellation, human approvals, artifacts, tools, model-provider boundaries, Temporal orchestration, and optional session-scoped sandboxes. It is not Software Factory: it has no Tickets, GitHub issue workflow, pull-request lifecycle, CI policy, merge policy, or repository-worker product domain.

The repository includes three complete examples: Durable Chat, Workspace Agent, and Research Dossier. Examples consume only the public HTTP contract and Go SDK. They are executable compatibility tests, not internal implementation clients.

## Priority order

Resolve every trade-off in this order:

> Legibility > Correctness > Operability > Economy

Testability is a floor beneath all four and is never traded.

- **Legibility:** a file must make its responsibility, assumptions, and failure mode clear in isolation. Prefer deep modules with narrow doors, typed invariants, and explicit names.
- **Correctness:** parse external input once at the boundary; model invalid states out; fail loudly and helpfully instead of silently accepting a bad default.
- **Operability:** an unattended session must be observable, cancellable, resumable, and auditable. Record decisions, not unbounded payloads. Use structured logs, metrics, traces, and durable event records.
- **Economy:** spend model tokens and human time only for a demonstrated correctness or operability gain. Do not make micro-performance an architectural priority in a model- and network-bound service.

## Mechanical walls

An agent's memory is not a control. Enforce important rules with types, linters, tests, generated checks, and CI:

- `os.Getenv`/`os.LookupEnv` are legal only in configuration loading.
- Wall-clock time is legal only in the system clock implementation. Tests use a fake clock; no test waits for real time.
- Entropy is injected and built only at a composition root.
- `fmt.Print*` is not application logging. Use injected JSON `slog` loggers.
- Ignored errors, blanket linter suppressions, bare `any`, and silent `recover` are prohibited.
- Third-party SDK types stay inside their adapter package. The public SDK, kernel, workflow, and domain packages use runtime-owned types.
- Generated SQL, OpenAPI, SDK reference, docs reference, and clients are regenerated by their owning command and verified clean; never hand-edit them.
- `go test -race` is required by the complete verification gate.

The repository's linter configuration is the executable version of these rules. If it fires, fix the code rather than weakening the wall.

## Domain and dependency direction

```text
public Go SDK / public HTTP contract
                 │
                 ▼
API and event transport ──► runtime application ──► kernel
                                         │              ▲
                                         ▼              │
Temporal, model, tools, sandbox, blobs, databases ─────┘
```

- The kernel owns deterministic state transitions and domain invariants. It imports no Temporal SDK, HTTP framework, provider SDK, blob implementation, sandbox backend, database driver, or telemetry exporter.
- Temporal is a private adapter. A Session maps to a workflow execution chain; input maps to an Update/Signal; model/tool/sandbox effects are activities. No Temporal type crosses the public API or SDK boundary.
- Workflows are replay-sensitive code. They use only `workflow.Context`, `workflow.Now`, `workflow.Sleep`, `workflow.Go`, deterministic data, and activities. Never use real time, I/O, environment, goroutines, random values, or provider clients inside a workflow.
- Any workflow command-sequence change is a history-compatibility change. Use `workflow.GetVersion` at the changed command branch, add replay tests for retained histories, and document the retention/removal decision.
- Provider, sandbox, blob, database, and protocol libraries are sealed in narrow adapters. Consumer-side interfaces remain small. Accept interfaces and return concrete types.
- Do not create `util`, `common`, `helpers`, `shared`, or grab-bag packages. Extract a micro-library only after the third demonstrated use.

## Identity, time, errors, and concurrency

- Every user-facing durable entity has a typed Stripe-style identifier generated by one central ID service; it is never a raw string at an API/domain boundary. Prefixes, parsing, validation, and JSON/database representation have contract tests.
- Respect authority: Temporal execution/run IDs and blob content digests are external technical identities, not substitutes for runtime Session/Turn/Artifact IDs.
- Time is UTC. Wire times are RFC3339 UTC. Raw numeric variable names carry units (`sizeBytes`, `limitSeconds`); `time.Duration` values do not.
- `context.Context` is first, threaded through, never stored in a struct, and cancellation is honoured. Use no unmanaged goroutines. Workflow code follows Temporal's distinct context and concurrency rules.
- Wrap errors with action and relevant safe identity: `fmt.Errorf("store artifact %s: %w", artifactID, err)`. Classify retryability at the Temporal adapter boundary. A malformed request or invariant violation is non-retryable; transient external failure is retryable. Do not build parallel untyped retry policy in leaf code.
- Secrets, refresh tokens, authorization headers, raw user prompts, model reasoning, and unbounded tool output never enter logs, Temporal history, public events, test fixtures, or generated docs. Redacted types must implement safe formatting and logging.

## Testing: test-driven and layered

Write the behaviour tests and acceptance criteria before implementation. It is fine to batch a coherent red suite before implementing it; do not write implementation first and retrofit confirmation tests.

1. Unit tests are hermetic: no network, subprocess, filesystem, wall clock, randomness, real provider, real sandbox, or real database. Inject a fake at every edge.
2. Workflow tests use Temporal's testsuite with mocked activities and virtual time. Compatibility changes add replay tests from retained histories.
3. Adapter contract tests run every implementation against the same fake/contract suite (blob stores, secret stores, sandbox backends, model streams where applicable).
4. Integration tests start named real dependencies locally and do not hide an unavailable dependency as a passing test. They are bounded, cleanup-safe, and documented.
5. End-to-end tests use the local Tilt stack, public API/SDK, real event streaming/reconnection, artifacts, sandbox lifecycle, a human approval, cancellation, and worker restart/recovery. They record machine-readable evidence.
6. No sleeps in tests. Advance fake or virtual time, await explicit conditions with bounded contexts, and make retry paths deterministic.

Do not claim a live proof that has not run. State the exact proof level: unit, workflow, integration, local Tilt E2E, or Linux/Firecracker E2E.

## Sandbox and tools

- A model requesting a tool is not authorization to execute it. Persist the requested call, evaluate policy/capabilities, optionally await a human approval, then persist the execution attempt and result separately.
- All process execution is argv-only: explicit argument arrays, never shell interpolation. It is context-bounded, records exit status and capped output, and is behind a fakeable interface.
- Sandboxes are session-scoped. Credentials and capabilities are command-scoped and least-privilege. A sandbox never receives a model refresh token or control-plane credential.
- Loss, restart, teardown, artifact upload, network policy, and approval/cancellation interactions are first-class states with tests. A best-effort cleanup is not correctness proof.

## Logs, metrics, and events

- Build JSON `slog` at composition roots and inject it. Include stable safe correlation fields such as session ID, turn ID, workflow ID, activity, provider, tool name, and sandbox ID.
- Log state transitions and policy decisions, not every leaf operation. Bound metric-label cardinality. Do not emit secret or content-bearing values.
- Public event streams are cursor-addressable append-only records. A reconnect from a cursor is tested. Transient provider deltas may be delivered to a connected caller but must not be treated as the sole durable evidence of a completed turn.

## Public surface and documentation

- The public Go SDK depends only on the public HTTP/event contract. It must not import runtime internals or implementation dependencies.
- Public API changes require OpenAPI generation, SDK documentation, Astro Starlight docs, runnable examples, changelog/release notes as applicable, and an explicit compatibility decision.
- Run `refresh-agent-runtime-docs` whenever public capabilities, routes, configuration, examples, installation steps, commands, security/operator guidance, or debugging paths change.
- The refresh skill uses current source and passing executable contracts as truth. It regenerates only declared output atomically, protects curated sections, supports check mode, validates docs and examples, and presents the exact diff. Never advertise planned behaviour as implemented.

## Completion gates

Use the actual commands listed in the root task runner. The intended vocabulary is:

```text
tilt up             start the isolated local stack
just test           hermetic unit and workflow tests
just integration    named real-dependency tests
just e2e            full public-system proof against Tilt
just docs           serve the documentation site
just docs-check     regenerate/check docs, links, snippets, and site build
just verify         all required checks, including generated-diff checks
```

Do not add a command to this file until it exists and has a tested implementation. Done means the relevant gates were run successfully and their exact scope is reported; it never means "the code looks complete."
```

## Required first implementation changes

1. Put the adapted full SoftwareStyle rulebook into the root `AGENTS.md`, retaining the priorities and mechanical rules above.
2. Add a repository-specific `.golangci.yml` that implements only rules whose package paths already exist; add more walls as packages arrive.
3. Add the two repo-local skills named above and their testable refresh generator before the public docs/API surface grows.
4. Replace the proposed command block with a real `Justfile` as each command becomes executable.

This avoids a dishonest early `AGENTS.md`: agents receive the strong style standard immediately without being instructed to run nonexistent paths.
