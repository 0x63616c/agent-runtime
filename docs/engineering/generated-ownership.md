# Generated artifact ownership

`docs/planning/requirements/master-requirements.md` supplies permanent IDs and
`docs/planning/work-map.md` supplies exactly one terminal milestone owner. The
requirement generator atomically owns only:

- `internal/milestone/manifest.go`
- `evidence/requirements-catalog.json`

The documentation refresh runner atomically owns only the outputs declared in
`skills/refresh-agent-runtime-docs/source-manifest.json`; at M0 that is:

- `website/docs/reference/generated/source-inventory.mdx`

Curated paths in that manifest are read-only inputs and are never generator
destinations. `just docs-check` compares generated bytes without writing;
`just docs-generate` refuses dirty tracked output and every existing untracked
output, while allowing a genuinely missing output bootstrap, and presents the
bounded staged, unstaged, and untracked documentation diff after validation.

`evidence/requirements-ledger.json` is curated durable state. The generator
may validate it but must never create, overwrite, or infer its statuses or
evidence. Duplicate terminal ownership, missing ownership, unknown IDs,
non-positive weights, drift, or partial ledgers fail visibly. Explicit
non-terminal contribution rows do not transfer ownership.

Run `go run ./cmd/generate-requirement-manifest --check` or `just check` after
changing binding requirements or the work map. Change generator inputs and
implementation together; never hand-edit generated output. Future OpenAPI, SDK,
configuration, and example reference generators extend the same explicit
manifest instead of scanning or rewriting curated prose.

The runtime OpenAPI route generator owns only:

- `internal/runtimeapi/openapi_routes_gen.go`
- `sdk/go/openapi_routes_gen.go`

Its sole authority is `api/openapi/openapi.yaml`; run
`go run ./cmd/generate-runtime-openapi --check` or `just check`. The OpenAPI
document and curated reference prose are never generated by this command.
